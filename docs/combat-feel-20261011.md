## 1. 本次原创机制开发（静态可读 + 独立代码运行）

### 1.1 命中顿帧：有限时长的物理冻结

- 修改 [prototype/combat-core.mjs](../prototype/combat-core.mjs)：增加 `hitstopSeconds=0.04`（40ms，**原创设计值**）以及 `hitstopRemaining`。
- **机制定义**：有效命中后写入顿帧剩余时间。每个 1/120s 固定步长推进全局 `time`，若顿帧仍生效则递减剩余时间并跳过该步的浮空位移、重力和倒地倒计时计算；命中失败或节奏禁止不会刷新顿帧。进入保护强制起身时清除残留顿帧，确保保护状态不会被旧顿帧延后。
- **限制**：此处仅冻结被测敌人的物理/计时，不是引擎级动作帧、音效、攻击者与受击者“双边顿帧”；动作前摇、后摇、真正的角色击中动画/特效均未实现。

### 1.2 单次可选低幅触地反弹

- 增加 `groundBounceVelocity=0`（默认关闭）、`groundBounceCount=1`。
- 上挑重置可反弹次数；首次下降接地时如果反弹开关已启用，触发 `ground-bounce` 事件并向上赋予设定速度，继续保持 `airborne`；次数用尽后第二次落地进入 `down` 并记录 `landed`。正在反弹阶段不可使用仅适用于倒地状态的扫地攻击。
- **限制**：反弹时刻的受击动作、躺地姿态和受击碰撞盒仍为原型简化状态；反弹开关关闭时原有落地规则保持不变。

### 1.3 HTML 交互

- 更新 [prototype/standalone.html](../prototype/standalone.html)，内联代码与最新核心 Git Blob 对齐；在参数面板新增 `命中停顿 0–150ms` 与 `触地反弹初速 0–4` 两个滑块，并在 HUD 增加剩余顿帧读数，在日志里区分 `ground-bounce` 和 `landed`。
- 仍保留原 `上挑/空追/扫地/高位斩`、自动连招及参数调节。浏览器界面不依赖 DNF 原版贴图、音频或联网服务。

### 2.1 实测轨迹样本（原创模型，120Hz 步进）

上挑初速10.5、重力22，不进行空中追加攻击，角色初始地面坐标为0。用 Node 实际循环至 `state==="down"` 并记录事件：

| 配置 | 最高点（世界单位） | 最终进入倒地时间 | 反弹事件 |
|---|---:|---:|---:|
| 关闭命中顿帧，关闭反弹 | 2.4721 | 0.9500秒 | 0 |
| 默认 40ms 顿帧，关闭反弹 | 2.4721 | 0.9917秒 | 0 |
| 默认 40ms 顿帧，反弹初速2且仅反弹一次 | 2.4721 | 1.1667秒 | 1，首次触地约0.9917秒 |

**解释范围**：浮空最高点不变，默认顿帧使最终落地约延后0.0417秒；开启低幅反弹再次延后约0.175秒。这只是由离散模拟及原型参数计算得到的测试证据，不说明 DNF 原版是否存在或采用同样反弹模型，也不能证明主观打击感改善。
